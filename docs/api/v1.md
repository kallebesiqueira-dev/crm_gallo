# Gallo CRM — Public API v1

Programmatic access to your CRM data over HTTPS. The public API is a thin,
versioned adapter over the same business logic the app uses, so audit trails,
activity timelines, outbox/webhook events, ownership defaults and per-tenant
isolation behave identically whether a request comes from the browser or your
integration.

- **Base URL:** `https://api.gallo-crm.com`
- **Version prefix:** `/api/v1`
- **Format:** JSON request and response bodies; UTF-8.
- **Auth:** API key as a bearer token (see below).

---

## Authentication

All `/api/v1` endpoints require an **API key** presented as a bearer token:

```
Authorization: Bearer crmk_<org>_<secret>
```

### Getting a key

An organization **admin** mints keys in **Settings → API keys** (or via
`POST /api/api-keys` from an authenticated admin session). The plaintext key is
shown **once** at creation and stored only as a hash afterward — copy it then;
it cannot be retrieved later. Revoke a key any time from the same screen.

A key carries one or both **scopes**:

| Scope   | Grants            |
|---------|-------------------|
| `read`  | `GET` requests    |
| `write` | `POST` (mutations) |

Keys default to `read`-only (least privilege). A key may also have an optional
expiry.

### Auth errors

| Status | When |
|--------|------|
| `401 Unauthorized` | missing / malformed `Authorization: Bearer` header, or an unknown/expired/revoked key. Carries `WWW-Authenticate: Bearer`. |
| `403 Forbidden` | the key is valid but lacks the scope the verb needs (e.g. a `read` key calling `POST`). |

The key embeds its organization, so it can only ever read or write data in the
org it belongs to — there is no way to reach another tenant's data with it.

## Versioning

Every response carries the current version:

```
X-API-Version: v1
```

When a version is scheduled for retirement, its responses additionally carry
[RFC 8594](https://www.rfc-editor.org/rfc/rfc8594) headers — `Deprecation: true`
and `Sunset: <http-date>` — so you get programmatic advance notice. `v1` is
current and **not** deprecated today.

---

## Rate limiting

Each API key is rate-limited independently (per-minute fixed window). On exceed:

```
HTTP 429 Too Many Requests
Retry-After: 60
```

Back off and retry after the indicated window.

---

## Pagination

List endpoints use **keyset (cursor) pagination** — stable under inserts, no
deep-offset cost.

**Query params**

| Param   | Default | Notes |
|---------|---------|-------|
| `limit` | `50`    | 1–200 |
| `cursor`| –       | opaque token from the previous page's `next_cursor` |

**Envelope**

```json
{
  "items": [ /* … */ ],
  "next_cursor": "b64-opaque-or-null",
  "has_more": true
}
```

Fetch the next page by passing `cursor=<next_cursor>`. When `has_more` is
`false`, `next_cursor` is `null` and you've reached the end.

---

## Errors

Errors are JSON with a `detail` field:

```json
{ "detail": "Lead not found" }
```

| Status | Meaning |
|--------|---------|
| `400` | malformed request |
| `401` | not authenticated (see Auth errors) |
| `403` | authenticated but not authorized for the verb |
| `404` | resource not found (or not in your org) |
| `422` | request body failed validation (FastAPI validation error shape) |
| `429` | rate limit exceeded |

## Endpoints

### Leads

#### `GET /api/v1/leads`
List leads (cursor-paginated).

| Query | Notes |
|-------|-------|
| `stage` | filter by lead stage (`new`, `qualified`, `won`, `lost`, …) |
| `q` | search by name / email / company |
| `limit`, `cursor` | pagination (see above) |

Returns a `CursorPage<Lead>`.

#### `POST /api/v1/leads`
Create a lead. Requires the `write` scope. Returns `201` + the created `Lead`.

#### `GET /api/v1/leads/{lead_id}`
Fetch one lead by id. `404` if it doesn't exist in your org.

### Customers

#### `GET /api/v1/customers`
List customers (cursor-paginated). Query: `q` (search), `limit`, `cursor`.
Returns a `CursorPage<Customer>`.

#### `POST /api/v1/customers`
Create a customer. Requires the `write` scope. Returns `201` + the `Customer`.

#### `GET /api/v1/customers/{customer_id}`
Fetch one customer by id.

## Schemas

### Lead — create body

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `first_name` | string | ✅ | 1–120 chars |
| `last_name` | string | ✅ | 1–120 chars |
| `email` | string | – | valid email |
| `phone` | string | – | |
| `company` | string | – | |
| `industry` | string | – | |
| `country` | string | – | ISO-3166 alpha-2 (2 chars) |
| `company_size` | integer | – | ≥ 0 |
| `budget` | number | – | ≥ 0 |
| `source` | string | – | |
| `notes` | string | – | |
| `stage` | string | – | defaults to `new` |
| `owner_id` | uuid | – | defaults to the key's principal |
| `team_id` | uuid | – | |
| `company_id` | uuid | – | link to a Company |
| `custom_fields` | object | – | org-defined custom fields |
| `contact_consent_at` | datetime | – | GDPR consent timestamp |
| `consent_source` | string | – | GDPR consent source |

**Lead — response** adds: `id`, `version` (optimistic-locking), `created_at`,
`updated_at`, and AI fields `ai_score`, `ai_priority`, `ai_next_action`,
`ai_conversion_probability`, `ai_risk_analysis`, `ai_scored_at`.

### Customer — create body

Same contact fields as Lead (`first_name`/`last_name` required; `email`,
`phone`, `company`, `industry`, `country`, `notes`, `company_id`,
`custom_fields`, `owner_id`, GDPR consent), plus `address` and `website`.
**Response** adds `id`, `version`, `created_at`, `updated_at`, `ai_summary`,
`ai_summary_updated_at`.

## Examples

List the first page of qualified leads:

```bash
curl -s https://api.gallo-crm.com/api/v1/leads?stage=qualified&limit=20 \
  -H "Authorization: Bearer $GALLO_API_KEY"
```

Create a lead (needs a `write`-scoped key):

```bash
curl -s -X POST https://api.gallo-crm.com/api/v1/leads \
  -H "Authorization: Bearer $GALLO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"first_name":"Ada","last_name":"Lovelace","email":"ada@example.com","company":"Analytical Engines"}'
```

Page through customers:

```bash
# first page
curl -s "https://api.gallo-crm.com/api/v1/customers?limit=50" \
  -H "Authorization: Bearer $GALLO_API_KEY"
# next page — pass the previous response's next_cursor
curl -s "https://api.gallo-crm.com/api/v1/customers?limit=50&cursor=<next_cursor>" \
  -H "Authorization: Bearer $GALLO_API_KEY"
```
